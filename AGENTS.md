
# Agent instructions for this hackathon repo

You are helping a team in the State of the Art Hackathon 2026. Read this file first, then follow it for the whole session.

## Start of work

1. Read `BRIEF.md` (version and date at the top).
2. Read only the track file for the team's track in `tracks/`. Don't load the other tracks.
3. Ask the student which track and challenge they chose, and record the answer in `README.md`.
4. Plan within that challenge's scope. If an idea falls outside scope, say so before building it.

## During work

- Keep `AI_DISCLOSURE.md` up to date: tools used, and what each one was used for.
- Don't use partner or rights-holder data (Incantio catalogue, AI for Peace works, HFAS archive, Harlem CLxR session) unless the student has documented permission. Use placeholders labelled as such.
- Don't commit secrets. Keep keys in `.env`, which is git-ignored, and document required variables in `.env.example`.
- If a file or video shows identifiable people, remind the student that filming and publishing need consent.
- If `BRIEF.md` conflicts with an announcement from BASIX.MARKET, flag it and follow the official version.

## Before submitting

- Work through `SUBMISSION.md` and report each item as passed, failed, or not applicable.
- Don't submit on the student's behalf. The student submits on BASIX.MARKET.

## Never

- Claim a prize, a placement, or co-ownership on the team's behalf.
- Remove or hide AI use from the disclosure.
- Change the track or challenge without the student's explicit confirmation.
